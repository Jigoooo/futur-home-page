# FUTUR 랜딩 클래식 디자인 선택 복원 설계

## 1. 목표

현재 랜딩에서 사용자가 승인한 두 요소만 유지한다.

- 전체 화면 Hero 파티클과 `BUILT FOR WHAT’S NEXT.` 문구
- 배경 명도에 맞춰 색이 바뀌는 현재 링·도트 커스텀 커서

Hero 이후의 화면은 팀 소개가 실제로 렌더링되던 Git 기준점 `12fa1c8`의 클래식 랜딩 디자인으로 돌아간다. 단, 검증되지 않은 숫자·고객 후기·완료 사례를 증거처럼 다시 노출하지 않는다.

## 2. 검토한 복원 방식

### A. 선택 복원 — 채택

`12fa1c8`의 레이아웃과 시각 스타일을 섹션 단위로 복원하고, 현재 Hero·커서와 문의 서버 보안 경계는 유지한다. 문의 화면 역시 현재 시네마틱 폼을 남기지 않고 `12fa1c8`의 TSX·필드 구성·CSS 소스에서 복원한다. 과거의 검증되지 않은 증거 섹션은 제외한다.

- 장점: 사용자가 기억하는 팀 소개 시점의 인상을 되찾으면서 현재 기능 안정성을 보존한다.
- 단점: 과거 커밋을 통째로 되돌리는 방식보다 파일별 통합 작업과 회귀 검증이 더 필요하다.

### B. `12fa1c8` 전체 롤백 후 Hero·커서 재적용 — 제외

- 장점: 과거 화면을 가장 빠르게 그대로 재현할 수 있다.
- 단점: 이후 보강된 문의 전송·서버 검증·접근성·SSR 경계까지 함께 퇴행하며, 숫자·후기·완료 사례도 다시 들어온다.

### C. 현재 섹션 구조에 과거 스타일만 흉내 내기 — 제외

- 장점: 코드 변경량이 작다.
- 단점: 사용자가 요청한 “팀 소개가 있었던 그때”의 구성과 리듬을 되찾지 못하고, 현재 시네마틱 섹션의 골격이 남는다.

## 3. 최종 페이지 구성

페이지 순서는 다음과 같다.

1. Hero — 현재 구현 보존
2. 서비스
3. 기술 역량
4. 팀 소개
5. 진행 방식
6. 운영·유지보수
7. FAQ
8. 문의
9. Footer

다음 현재 섹션은 제거한다.

- 품질 기준
- 검토 방식
- Layered Merge 서비스 장면
- 곡선 마스크 기반 진행 장면

다음 과거 섹션은 복원하지 않는다.

- Hero 다음 숫자 지표와 `TrustSection`
- 고객 후기와 `ReviewsSection`
- 완료 프로젝트처럼 보이는 익명 사례와 `CaseStoriesSection`

## 4. 보존 경계

### Hero

- `100vw × 100svh` 전체 화면 파티클 배경을 유지한다.
- `BUILT FOR WHAT’S NEXT.` 두 줄 문구, 현재 반응형 크기와 콘텐츠 여백을 유지한다.
- WebGL 실패, reduced-motion, Save-Data, 포인터 반응, 가시성 정지·재개 경로를 유지한다.
- 과거 Hero 배경·카피·분할 레이아웃은 복원하지 않는다.

### 커스텀 커서

- 현재의 심플한 링·도트 구조를 유지한다.
- Hero, 밝은 본문, 어두운 문의 영역, 버튼 위에서 semantic cursor tone이 전환되어야 한다.
- coarse pointer와 reduced-motion에서는 네이티브 커서를 사용한다.
- 과거의 큰 라벨형 커서와 `WEB`, `SEND` 같은 커서 텍스트는 복원하지 않는다.

### 문의 기능과 보안

- 문의 화면은 `12fa1c8`의 `contact-section`, `contact-brief-fields`, `contact-identity-fields`, `custom-select`, contact config와 CSS 파일 본문 자체를 출발점으로 복원한다.
- 단계·필요 서비스·일정·예산·담당자 정보·문의 내용·필수 동의로 이어지는 과거 폼 구성과 좌우 배치를 복원한다.
- 현재 서버 입력 계약과 일치하는 필드명, 클라이언트 검증, 전송 상태, 실패 시 이메일 대체 경로는 과거 UI에 다시 연결한다.
- `평균 회신 24시간`, `빠른 범위 검토`처럼 SLA나 보장으로 읽힐 수 있는 과거 문구는 복원하지 않는다.
- 서버 allowlist, rate limit, idempotency, honeypot, form-age, test-address guard를 변경하지 않는다.

### 버튼과 접근성

- 현재 pill 버튼의 spotlight, sheen, focus-visible, press 피드백을 유지한다.
- semantic heading, 키보드 탐색, disclosure, dialog, form label 연결을 유지한다.
- JavaScript가 늦거나 비활성화되어도 모든 본문과 핵심 CTA가 보여야 한다.

## 5. 복원할 클래식 디자인

### Header

- `12fa1c8`의 단정한 캡슐형 헤더 비례와 탐색 리듬을 복원한다.
- 내비게이션은 `서비스`, `기술`, `팀`, `프로세스`, `FAQ`, `문의`로 구성한다.
- Hero 위와 밝은 본문 위에서 대비가 유지되도록 현재 surface 전환 로직은 재사용한다.

### 서비스

- 과거의 명확한 서비스 정보 구조와 카드 비례를 복원한다.
- 검증 가능한 제공 범위만 사용하며 성과·응답 시간·완료 수치를 넣지 않는다.
- 현재 Layered Merge 장식과 해당 GSAP 장면은 제거한다.

### 기술 역량

- 기술 이름을 과시용 배지 묶음이 아니라 실제 제공 영역을 설명하는 보조 정보로 사용한다.
- 현재 프로젝트가 실제로 사용하는 기술과 수행 가능한 범주만 남긴다.
- 숙련도, 경력 연수, 인증처럼 확인되지 않은 수준 표기는 사용하지 않는다.

### 팀 소개

- `12fa1c8`의 팀 섹션 레이아웃을 복원한다.
- 확인 가능한 이름·역할·업무 책임만 표시한다.
- 인원수, 경력 연수, 고객사, 수행 실적을 새로 만들지 않는다.
- 개인 정보나 사실관계가 확인되지 않는 항목은 코드에 넣지 않는다.

### 진행 방식과 운영·유지보수

- 과거의 단계형 프로세스와 운영 정책 레이아웃을 복원한다.
- `24/7`, `4시간 응답`, 고정 일정, 자동 NDA 같은 보장 문구는 사용하지 않는다.
- 협의, 범위 확인, 구현, 검증, 인수인계처럼 실제 작업 태도만 설명한다.

### FAQ·문의·Footer

- 과거의 시각 밀도와 배치로 복원한다.
- 현재 FAQ disclosure 동작을 유지한다.
- 문의는 과거의 밝은 카드·폼·필드 구성까지 소스 자체로 복원하고, 현재 서버 보안 경계만 뒤에서 유지한다.
- Footer에는 확인 가능한 법인·연락처·정책 링크만 둔다.

## 6. 모션 원칙

- Hero 파티클과 현재 버튼 인터랙션은 유지한다.
- Hero 이후에는 과거 디자인의 절제된 in-view reveal을 사용한다.
- 현재 시네마틱 장면 전용 clip-path, parallax, merge, path drawing 모션은 제거한다.
- 모든 섹션에 같은 큰 움직임을 반복하지 않는다.
- reduced-motion에서는 장식 모션 없이 최종 상태를 즉시 보여준다.

## 7. 구현 방식

- `git checkout`이나 전체 revert로 과거 트리를 덮어쓰지 않는다.
- Hero·커서·문의 서버 보안 예외를 제외한 랜딩 컴포넌트와 CSS는 `git show 12fa1c8:<path>`의 파일 본문 자체를 출발점으로 선택 복원한다. 문의 UI 컴포넌트와 CSS는 이 예외에 포함되지 않는다.
- 현재 컴포넌트 구조에 과거 색·간격·토큰을 흉내 내는 방식은 사용하지 않는다. 과거 TSX·CSS를 먼저 복원한 다음 사실 경계와 현재 호환성에 필요한 최소 변경만 적용한다.
- 허용되는 최소 변경은 검증되지 않은 필드·문구 삭제, 현재 Hero·커서 연결, 문의 보안 로직 연결, 접근성·테스트용 semantic marker로 한정한다.
- 클래식 본문이 사용하는 과거 token과 global canvas도 과거 소스를 기준으로 복원하되, 현재 Hero의 `--charcoal`·`--paper`와 cursor 활성화 규칙은 호환 token으로 유지한다.
- 현재 Hero, particle engine/shader, custom cursor, contact server 경계와 충돌하는 과거 코드는 가져오지 않는다. 문의의 클라이언트 화면은 과거 소스를 복원한 뒤 현재 서버 계약에 필요한 최소 호환 변경만 적용한다.
- 제거된 타입·설정·에셋은 실제 렌더링에 필요한 경우만 복원한다.
- 루트 `DESIGN.md`는 구현 완료 시 이 설계를 최종 권위로 반영한다.

## 8. 검증 계약

### 보존 회귀

- Hero가 데스크톱과 모바일에서 전체 뷰포트를 채운다.
- 파티클 렌더링·포인터 반응·reduced-motion·Save-Data 경로가 유지된다.
- 커서 링·도트가 밝고 어두운 표면에서 대비를 바꾸며 coarse/reduced 환경에서 비활성화된다.
- 문의 전송·실패 복구·서버 보안 경계 테스트가 모두 통과한다.
- 문의의 단계·서비스·일정·예산·담당자·내용·동의 필드와 과거 클래식 좌우 레이아웃이 복원된다.

### 복원 회귀

- 팀 섹션과 팀 내비게이션 앵커가 존재한다.
- 서비스, 기술 역량, 팀, 진행 방식, 운영·유지보수, FAQ, 문의가 승인된 순서로 렌더링된다.
- 데스크톱 `1280×720`, 모바일 `390×844`에서 가로 overflow가 없다.
- 과거 클래식 카드·간격·배경 리듬이 브라우저 캡처에서 확인된다.

### 제거 회귀

- 숫자 지표, 고객 후기, 익명 완료 사례가 DOM에 없다.
- 현재 품질 기준·검토 방식·Layered Merge 장면이 DOM에 없다.
- `24/7`, `4시간 응답`, 경력 연수, 자동 NDA 같은 확인되지 않은 문구가 없다.

### 최종 게이트

- 대상 Playwright 회귀
- 전체 `pnpm test:e2e`
- `pnpm lint`
- `pnpm build`
- 접근성 검사
- 런타임 오류 검사
- `graphify update .`
- `git diff --check`

## 9. 완료 조건

Hero와 커서는 현재 디자인 그대로 보이며, 그 아래부터는 팀 소개가 있던 시기의 클래식 FUTUR 랜딩으로 자연스럽게 이어진다. 과거 디자인을 복원했더라도 검증되지 않은 증거와 이후 보강된 보안·접근성 퇴행은 없어야 한다.
