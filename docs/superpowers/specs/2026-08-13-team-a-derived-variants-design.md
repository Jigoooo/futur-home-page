# Team A Derived Variants Design

## Goal

현재 Team A의 역할 정보와 문구는 유지하면서, 반복되는 3열 행 구조에서 생기는 PPT 인상을 제거한다. 기존 Team B와 Team C는 폐기하고, Team A에서 파생한 세 가지 레이아웃을 내부 비교용으로 제공한다.

## Design Read

- Page: SI 및 SaaS 기업 랜딩 페이지의 팀 소개 섹션
- Audience: 프로젝트 발주 담당자와 협업 파트너
- Direction: 차분하고 신뢰감 있는 B2B 톤을 유지한 비대칭 편집형 구성
- Design variance: 8
- Motion intensity: 5
- Visual density: 3
- Styling foundation: 기존 React와 CSS Modules를 유지하며 새 디자인 시스템이나 의존성을 추가하지 않는다.

## Shared Content

세 안 모두 다음 요소를 그대로 사용한다.

- 섹션 제목: `프로젝트를 움직이는 역할들.`
- 섹션 설명: `각자의 전문 영역을 나누되, 프로젝트 목표와 사용자의 업무 흐름은 함께 이해합니다.`
- 역할: PM, PLAN, FE, BE, OPS
- 역할명, 책임 설명, 역할 범위 태그

`OUR TEAM` 칩은 다시 추가하지 않는다. 고객, 인원수, 성과, 경력과 같은 검증되지 않은 정보도 만들지 않는다.

## Comparison Routing

- `?team=a1`: Offset Editorial, 기본값
- `?team=a2`: Vertical Chapters
- `?team=a3`: Interactive Field
- 기존 `?team=b`, `?team=c`는 지원하지 않고 기본값 A1으로 처리한다.
- 비교용 쿼리 파라미터는 개발 환경에서만 동작한다.

## A1: Offset Editorial

추천안이다. 역할 5개를 좌우 2열에 엇갈리게 배치하고, 각 역할을 카드가 아닌 독립된 텍스트 덩어리로 표현한다.

- PM, FE, OPS와 PLAN, BE가 서로 다른 세로 흐름을 만든다.
- 역할 코드는 작은 보조 정보로 두고 역할명이 첫 번째 시선이 되도록 한다.
- 설명은 역할명 바로 아래에 붙이고 역할 범위는 쉼표나 별도 줄의 평문으로 표시한다.
- 배경, 테두리, 그림자, 둥근 카드 형태를 사용하지 않는다.
- 동일한 높이와 동일한 폭을 강제하지 않는다.
- 스크롤 진입 시 좌우 위치에 맞춰 12px 안쪽에서 나타나며, 역할별로 짧은 시차를 둔다.
- 호버는 제목 색상과 3px 이하의 이동만 사용한다.

이 안의 목적은 Team 섹션을 Services 섹션의 카드나 목록과 가장 확실하게 구분하는 것이다.

## A2: Vertical Chapters

역할을 표의 행이 아니라 길이와 들여쓰기가 다른 다섯 개의 세로 챕터로 구성한다.

- 각 역할명은 넓은 공간을 차지하는 큰 제목으로 표시한다.
- 설명과 역할 범위는 제목 아래의 좁은 텍스트 열에 배치한다.
- 항목별 최대 너비와 시작 위치를 달리해 규칙적인 목록 인상을 줄인다.
- 구분선은 각 항목마다 반복하지 않고, 전체 흐름을 나누는 데 필요한 경우 최대 두 번만 사용한다.
- 진입 모션은 아래에서 위로 14px 이동하며 순차적으로 나타난다.
- 호버 시 역할 범위의 대비가 높아지지만 배경은 생성하지 않는다.

이 안은 가장 차분하고 읽기 쉽지만 A1보다 섹션 높이가 길어진다.

## A3: Interactive Field

다섯 역할을 비대칭 공간에 펼쳐 놓고, 선택한 역할이 그 자리에서 확장되는 인터랙티브 구성이다. 기존 Team C의 메뉴와 상세 패널 분할 구조는 재사용하지 않는다.

- 기본 상태에는 역할 코드, 역할명, 한 줄 설명만 보인다.
- hover, focus, click, tap으로 역할을 활성화한다.
- 활성 역할은 같은 위치에서 설명과 역할 범위를 펼친다.
- 비활성 역할은 불투명도를 조금 낮추되 읽을 수 있는 대비를 유지한다.
- 키보드 포커스와 현재 선택 상태를 명확하게 표시한다.
- 포인터가 없는 환경에서는 클릭이나 탭으로만 상태를 바꾼다.
- 모바일에서는 비대칭 배치를 해제하고 한 열 확장 목록으로 전환한다.
- 상태 전환은 transform과 opacity만 애니메이션하며 높이 변화는 콘텐츠 영역을 미리 확보해 레이아웃 이동을 줄인다.

이 안은 PPT 인상은 가장 적지만, 정적 정보 섹션보다 사용자의 탐색 행동을 요구한다.

## Responsive Rules

- 1280px 이상에서는 각 안의 비대칭 구성을 유지한다.
- 768px에서 1279px 사이는 열 간격과 들여쓰기를 줄이고 텍스트 폭을 우선 확보한다.
- 767px 이하에서는 모든 안을 한 열로 바꾼다.
- 모바일에서 가로 스크롤, 잘린 설명, 우측 눌림이 없어야 한다.
- 역할명과 설명은 어떤 화면에서도 서로 다른 정렬 기준으로 분리하지 않는다.

## Motion and Interaction

- 모션의 목적은 역할 간 읽기 순서를 전달하거나 사용자 입력에 응답하는 것이다.
- 무한 반복 애니메이션, 장식용 SVG, 패럴랙스, 글로우, 마우스 추적은 사용하지 않는다.
- 진입 모션은 역할당 0.45초 이하, 시차는 0.07초 이하로 제한한다.
- hover 이동은 3px 이하로 제한한다.
- `prefers-reduced-motion: reduce`에서는 모든 역할이 즉시 최종 상태로 표시된다.

## Accessibility

- A1과 A2는 읽기 순서와 DOM 순서를 동일하게 유지한다.
- A3의 역할 선택 요소는 키보드 접근이 가능해야 한다.
- A3는 현재 활성 상태를 `aria-pressed` 또는 같은 수준의 명확한 상태 정보로 노출한다.
- 포커스 표시를 제거하지 않는다.
- 비활성 역할의 텍스트 대비도 WCAG AA 기준을 유지한다.

## Removal Scope

다음 기존 비교 구현은 신규 세 안이 동작한 뒤 제거한다.

- `TeamRoleWall`
- `TeamRoleExplorer`
- 관련 CSS Modules
- 기존 B와 C 전용 테스트 기대값

기존 A 구현은 A1의 출발점으로만 사용하며, 3열 역할 행 레이아웃은 남기지 않는다.

## Verification

- A1, A2, A3에서 역할 5개와 역할 범위 15개가 모두 노출되는지 확인한다.
- 기본 주소와 알 수 없는 `team` 값이 A1을 표시하는지 확인한다.
- 기존 `team=b`, `team=c`가 이전 컴포넌트를 표시하지 않는지 확인한다.
- A3를 hover, focus, click으로 조작할 수 있는지 확인한다.
- 390px 모바일 화면에서 세 안 모두 가로 넘침이 없는지 확인한다.
- reduced motion에서 모든 콘텐츠가 즉시 보이는지 확인한다.
- lint, build, 관련 Playwright 테스트, 접근성 테스트를 실행한다.
- 내부 브라우저에서 A1, A2, A3을 각각 별도 탭으로 열어 시각 비교한다.

## Non-goals

- 팀 문구 재작성
- 실제 팀원 프로필이나 사진 추가
- Services 섹션 변경
- 새로운 애니메이션 라이브러리 도입
- 최종안 선택 전 비교 쿼리 제거
